09 — Acceptance Criteria & Edge Cases

How we know a story is done

Acceptance criteria define how the team determines whether a user story has been successfully implemented — using the Customer Booking story as the example.

Customer Booking
As a

Customer

↓
I want to

book an available appointment

↓
So that

I can reserve a suitable time.

GIVEN

A customer has selected a service and an eligible service provider.

WHEN

The customer selects an available appointment time and confirms the booking.

THEN

The system creates the appointment and displays confirmation.

Important Edge Cases

⚠ Slot Becomes Unavailable

The system prevents the booking and asks the customer to choose another time.

⚠ Invalid Information

The system displays validation feedback.

⚠ Unauthorized Access

Users cannot access information or functionality outside their role.

⚠ Appointment Conflict

The system prevents overlapping appointments for the same provider.

Acceptance criteria make requirements testable and help define when a feature is complete.
